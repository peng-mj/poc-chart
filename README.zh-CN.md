# 抗量子 Chart 工具 - PQC Chart Tool

基于 NIST FIPS 204/203 标准的后量子密码学双向验签工具，使用 Ed25519 签名、ML-KEM 密钥封装和 AES-GCM 加密。

## 核心原理

### 密码学套件

| 组件 | 算法标准 | Go 标准库 | 说明 |
|------|----------|-----------|------|
| **持久身份** | Ed25519 | `crypto/ed25519` | 高效椭圆曲线签名，64 字节签名 |
| **临时会话** | ML-KEM-768 | `crypto/mlkem` | NIST FIPS 203，密文 1088 字节 |
| **对称加密** | AES-256-GCM | `crypto/aead` | 32 字节密钥，由 HKDF 派生 |
| **密钥派生** | HKDF-SHA256 | `crypto/hkdf` | 从共享秘密派生会话密钥 |

### 设计目标

1. **前向安全**：临时 ML-KEM 密钥对用完即毁
2. **双向验证**：客户端间互相验证对方身份
3. **抗量子攻击**：ML-KEM 提供量子安全密钥交换
4. **隐私保护**：持久私钥加密存储，永不以明文出现在网络

## 详细流程说明

### 阶段一：双向 ML-KEM 封装（建立加密管道）

```
目标：在不安全的网络上建立共享密钥，确保前向安全

Step 1: 发起方发送临时公钥
┌─────────────┐
│  Client A   │
└──────┬──────┘
        │ 生成临时 ML-KEM 密钥对 (tmp_priv_A, tmp_pub_A)
        │
        │ HandshakeRequest {
        │   KEMPublicKey: tmp_pub_A        // 1184 bytes
        │   AlgorithmSuite: "ML-KEM-768"
        │ }
        │
        ├─────────────────────────────────────────>
        │                                          │
        │                          ┌─────────────┐ │
        │                          │  Client B   │ │
        │                          └──────┬──────┘ │
        │                                 │        │

Step 2: 响应方封装并发送自己的公钥
                                        │ 生成临时密钥对 (tmp_priv_B, tmp_pub_B)
                                        │ 使用 tmp_pub_A 封装：ct_A, ss_B2A
                                        │
        │<────────────────────────────────│ HandshakeAgree {
        │                                  │   KEMPublicKey: tmp_pub_B   // 1184 bytes
        │                                  │   PeerCiphertext: ct_A      // 1088 bytes
        │                                  │ }
        │                                  │
        │  使用 tmp_priv_B 解封装 ct_A     │ 保存 ss_B2A（共享秘密）
        │  获得 ss_B2A                      │

Step 3: 发起方完成封装
        │ 使用 tmp_pub_B 封装：ct_B, ss_A2B
        │
        │ HandshakeFinish {
        │   Ciphertext: ct_B                // 1088 bytes
        │ }
        │
        ├─────────────────────────────────>│
        │                                    │ 保存 ss_A2B
        │                                    │
        │ 保存 ss_A2B                        │
        │                                    │
        ▼                                    ▼
     派生会话密钥                          派生会话密钥
     session_key = HKDF(ss_B2A || ss_A2B)   session_key = HKDF(ss_B2A || ss_A2B)
                                             │
                          ┌──────────────────┴──────────────────┐
                          │   加密管道已建立                   │
                          │   - 所有后续消息加密传输           │
                          │   - 临时私钥已安全擦除             │
                          └─────────────────────────────────────┘
```

**关键特性：**
- **前向安全**：临时密钥用完后立即擦除
- **双向贡献**：双方都对共享密钥有贡献，防止单方控制
- **密钥分离**：ss_A2B 和 ss_B2A 独立派生，增强安全性

### 阶段二：双向身份验证（在加密管道内）

```
前置条件：
- 会话密钥 session_key 已建立
- 双方已通过带外方式交换对方的 ID_Hash（持久公钥的 SHAKE-256 哈希）

Step 4-6: Client A 向 Client B 验证身份

┌─────────────┐                          ┌─────────────┐
│  Client A   │                          │  Client B   │
└──────┬──────┘                          └──────┬──────┘
       │                                         │
       │ 发送持久 Ed25519 公钥（加密）            │
       │ IdentityMsg {                           │
       │   PublicKeyEncrypted: AES-GCM(DSA_pub_A)│
       │ }                                       │
       ├────────────────────────────────────────>│
       │                                         │
       │                                         │ 解密获得 DSA_pub_A
       │                                         │ 验证: SHAKE256(DSA_pub_A) == peer_id_hash_A
       │                                         │ ✓ 身份确认
       │                                         │
       │                                         │ 生成随机挑战 nonce_B
       │                                         │
       │                                         │ Challenge {
       │<────────────────────────────────────────│   NonceEncrypted: AES-GCM(nonce_B)
       │                                         │ }
       │                                         │
       │ 解密获得 nonce_B                        │
       │                                         │
       │ 签名挑战：                               │
       │ message = nonce_B || channel_binding    │
       │ sig_A = Ed25519Sign(DSA_priv_A, message)│
       │                                         │
       │ SignatureResponse {                     │
       │   SignatureEncrypted: AES-GCM(sig_A)   │
       │ }                                       │
       ├────────────────────────────────────────>│
       │                                         │
       │                                         │ 解密获得 sig_A
       │                                         │ 验证: Ed25519Verify(DSA_pub_A, message, sig_A)
       │                                         │ ✓ 签名有效 → Client A 身份确认
       │                                         │


Step 7-9: Client B 向 Client A 验证身份（对称过程）

        │                                         │ 发送持久 Ed25519 公钥（加密）
        │<────────────────────────────────────────│ IdentityMsg {
        │                                         │   PublicKeyEncrypted: AES-GCM(DSA_pub_B)
        │                                         │ }
        │                                         │
        │ 解密获得 DSA_pub_B                      │
        │ 验证: SHAKE256(DSA_pub_B) == peer_id_hash_B
        │ ✓ 身份确认
        │                                         │
        │ 生成随机挑战 nonce_A                    │
        │                                         │
        │ Challenge {                             │
        │   NonceEncrypted: AES-GCM(nonce_A)      │
        │ }                                       │
        ├────────────────────────────────────────>│
        │                                         │
        │                                         │ 解密获得 nonce_A
        │                                         │ 签名挑战
        │                                         │
        │                                         │ SignatureResponse {
        │<────────────────────────────────────────│   SignatureEncrypted: AES-GCM(sig_B)
        │                                         │ }
        │                                         │
        │ 解密获得 sig_B                          │
        │ 验证: Ed25519Verify(DSA_pub_B, message, sig_B)
        │ ✓ 签名有效 → Client B 身份确认
        │                                         │
        ▼                                         ▼
     ┌──────────────────────────────────────────────────┐
     │         双向身份验证完成                         │
     │   ✓ 双方都确认了对方的持久公钥                   │
     │   ✓ 双方都证明了私钥的所有权                    │
     │   ✓ 挑战-响应机制防止重放攻击                    │
     │   ✓ 管道绑定值确保会话完整性                      │
     └──────────────────────────────────────────────────┘
```

**安全特性：**
- **加密管道内验证**：持久公钥仅在加密管道内传输，防止窃听
- **带外哈希验证**：ID_Hash 通过带外方式交换，防止中间人攻击
- **挑战-响应**：使用随机 nonce，每次签名唯一，防止重放
- **管道绑定**：签名包含临时公钥哈希，绑定特定会话

### 阶段三：加密数据传输

```
数据格式：每条消息使用 AES-256-GCM 独立加密

发送方加密流程：
┌─────────────┐
│  Client A   │
└──────┬──────┘
       │ plaintext = "Hello secure world"
       │
       │ 生成随机 nonce (12 bytes)
       │
       │ ciphertext = AES-GCM-Seal(
       │   key: session_key,
       │   nonce: random_nonce,
       │   plaintext: plaintext
       │ ) → nonce || ciphertext || tag(16B)
       │
       ├─────────────────────────────────────────>
       │                                          │


接收方解密流程：
                                              ┌─────────────┐
                                              │  Client B   │
                                              └──────┬──────┘
                                                     │
                                                     │ 解析：nonce (12B) || ciphertext || tag (16B)
                                                     │
                                                     │ plaintext = AES-GCM-Open(
                                                     │   key: session_key,
                                                     │   nonce: nonce,
                                                     │   ciphertext: ciphertext,
                                                     │   tag: tag
                                                     │ )
                                                     │

                          ┌──────────────────────────┴──────────────────┐
                          │   每条消息特性                             │
                          │   • 独立随机 nonce，防止模式分析           │
                          │   • AEAD 认证标签，检测篡改                │
                          │   • 解密失败即丢弃，不泄露任何信息          │
                          └─────────────────────────────────────────────┘
```

│     │  生命周期：单次会话                             │   │

│                                                             │
└────────────────────────────────────────────────────────────┘

## 安全特性

### 1. 前向安全
- 临时 ML-KEM 密钥对每次握手重新生成
- 握手完成后立即擦除临时私钥
- 即使记录历史通信，也无法解密

### 2. 抗量子攻击
- ML-KEM-768 基于 Module-LWE 问题，量子计算机无已知多项式算法
- 未来可无缝切换到 ML-DSA（待 Go 标准库公开）

### 3. 防重放攻击
- 挑战-响应机制使用随机 nonce
- Nonce 缓存防止重复使用

### 4. 防中间人攻击
- 带外交换 ID_Hash 验证持久公钥
- 管道绑定值将签名与特定会话绑定

### 5. 完善前向保密
- 会话密钥由双方共同贡献派生
- 单方妥协无法推导历史会话密钥

## 使用方法

### 1. 生成身份
```bash
./bin/pqc-chart-tool generate
```
- 生成 Ed25519 持久密钥对
- 计算并显示 ID_Hash（32 字节十六进制字符串）
- 私钥加密存储，公钥明文存储

### 2. 查看 ID Hash
```bash
./bin/pqc-chart-tool show-id
```
- 显示当前身份的 ID_Hash
- 用于与对等方带外交换

### 3. 连接到对等方

#### 中继模式（通过 WebSocket 中继服务器）
```bash
./bin/pqc-chart-tool connect ws://relay-server:8080 <peer-id-hash>
```

#### 直连模式（点对点）
```bash
# 启动服务器模式（需要提供期望连接的对端 ID Hash）
./bin/pqc-chart-tool server <peer-id-hash> [端口]  # 默认端口：18080

# 从另一个终端连接
./bin/pqc-chart-tool connect <IP> <peer-id-hash>              # 使用默认端口 18080
./bin/pqc-chart-tool connect <IP>:<端口> <peer-id-hash>       # 使用自定义端口
```

**示例：**
```bash
# 终端 1 - 启动服务器（提供期望连接的对端 ID Hash）
./bin/pqc-chart-tool server d4e5f6a1b2c3...

# 终端 2 - 连接到服务器（提供服务器的 ID Hash）
./bin/pqc-chart-tool connect 127.0.0.1 a1b2c3...
```

- 通过中继服务器或直接 TCP 连接发起连接
- 执行完整握手和身份验证流程
- 建立加密通信通道

### 4. 帮助
```bash
./bin/pqc-chart-tool help
```
显示详细的使用信息和示例。

### 连接模式

#### 1. 中继模式
- 使用 WebSocket 中继服务器建立连接
- 适合 NAT 穿透和防火墙环境

#### 2. 直连模式（新增）
- 直接点对点 TCP 连接
- 无需中继服务器
- 默认端口：18080（可配置）
- 适合局域网环境和测试

详见 [直连模式测试指南](DIRECT_CONNECTION.md) 获取详细使用说明。

## 技术栈
- **语言**：Go 1.26.2
- **PQC 算法**：ML-KEM-768 (FIPS 203)
- **签名算法**：Ed25519（临时替代 ML-DSA）
- **对称加密**：AES-256-GCM
- **传输协议**：WebSocket

## 安全注意事项
